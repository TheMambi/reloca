# Known pitfalls

Symptom, cause and fix for traps this project has already hit. Read before touching the area named.

| Area | Symptom | Cause | Fix |
|---|---|---|---|
| Build | `pnpm build` stops with "Failed to fetch `Geist` from Google Fonts" | `next/font/google` downloads the font files during the build, so a blocked network or a Google Fonts outage breaks it | Load fonts from the `geist` package (`geist/font/sans`, `geist/font/mono`), which ships the files; keep `next/font/google` out of the app |
| Schemas | Saving one field resets others to their starting values (lease decision back to undecided, monthly premium back to 0) | Zod fills a `.default()` for every missing key, even after `.partial()`, so a patch schema built from a shape with defaults writes those defaults over saved data | Keep defaults on create schemas only. Build patches from the row schema's own fields with `.pick()`, `.partial()` and `.strict()`, as `schemas/lease.ts` does |
| Deploy | The build fails, or every page answers "Internal Server Error", and the log says "Reloca refuses to serve" | `RELOCA_MODE` is missing or mistyped, or private mode lacks a setting the message names. The app stops instead of guessing, because the old flag sent every value except `1` to the real database | Set `RELOCA_MODE` to `demo` or `private`, plus whatever the message names, in every environment that builds or runs the app, then redeploy |
| Mode | A new check reads `RELOCA_DEMO_MODE` or `RELOCA_MODE` directly and disagrees with the rest of the app | The mode is decided in one place, `appMode()` in `lib/mode.ts`, which also validates the settings private mode needs | Ask `appMode()`, or `isDemoMode()` in `lib/supabase/server.ts`. Do not read the mode variables anywhere else |
| Database | A query returns or changes rows it should not, or a new table is readable from outside | Since migration 0025 the server uses the service role key, which skips row level security. The database filters nothing for the app, and re-running an older migration grants `anon` access again | Put `.eq("user_id", requireUserId())` on every read, update and delete and set `user_id` on every insert; `lib/supabase/user-scope.test.ts` fails otherwise. Run 0025 again after re-running any earlier migration. See `docs/security-lockdown.md` |
| Database | A function added after the lockdown can be called with the anon key, even after `REVOKE ... FROM PUBLIC` | Supabase grants new functions and sequences to `anon` and `authenticated` by name through default privileges, and 0025 changed those for tables only | Migration 0026 closes the defaults for the role that runs it. Still write `REVOKE ALL ON FUNCTION ... FROM PUBLIC, anon, authenticated` in each migration that adds one, and run check 1 from `docs/security-lockdown.md` afterwards |
| Tests | A test or script stops with "This module cannot be imported from a Client Component module" | Server modules import `server-only`, which only loads under the `react-server` condition that Next sets for server code | Run it with `npx tsx --conditions=react-server <file>`. `pnpm test` already does |
| Lease | The letter, a task title or a deadline shows a notice period or deposit rule that is not the lease's | The 60-day notice and Colorado's 60-day deposit rule were once typed into the template, the task seeds and the event math | Take the notice period from `notice_days_required` (`noticeTerm`) and the deposit rule from `lib/lease/deposit-rules.ts`. Add a state there only with a citation; an unlisted state shows no date and asks the user to check |
| Lease | Checklist dates disagree with the lease tracker or the move date after an edit | Due dates are stored copies. Lease tasks were seeded once and never refreshed, and move-date offsets were applied only at insert | Lease tasks are built in `lib/lease/lease-tasks.ts` and rewritten by `updateLeaseTerms`. Move-seeded rows are shifted by `shiftMoveDependentDates`. A new stored date that depends on the lease or the move date needs the same treatment |
| Destinations | A pin or the rent benchmark disappears after an unrelated edit | The overlay refresh wrote null for every lookup that failed or was skipped, and the lookups cached failures for the life of the server | `overlayPatch` writes a missing value only when the address changed. `hud.ts` and `geocode.ts` cache answers, never timeouts or error responses |
| Forecaster | Bars cannot be ranked, or the worst case sits below a milder one | Totals covered different spans (12 months for one path, the months left for another) | Every bar in `computeForecast` covers today to 12 months after lease end. Keep a new path on the same span |
| Dates | A countdown is one day off, a task shows overdue on its due date, or a notice sent in the evening is recorded as a day late | "Today" was taken from UTC on the server and from the browser's zone on the client, so the two disagreed from late afternoon in US zones | Use `todayInZoneIso()` from `lib/dates.ts` everywhere. It reads `NEXT_PUBLIC_RELOCA_TIME_ZONE`. Never slice `new Date().toISOString()` for a calendar day |
| Dates | A date picker highlights or saves the day before the one shown | react-day-picker works in local time, and each form converted with UTC | Convert only with `isoToPickerDate` and `pickerDateToIso` from `lib/dates.ts` |
| Dates | Month counts or date windows differ between a laptop and the server | A date-only string parses as UTC midnight; reading it with local getters (`getMonth`, `getDate`, `setDate`) shifts it a day west of UTC | Do date-only arithmetic with `addDaysIso` and `daysBetweenIso`, or UTC getters. `pnpm test` runs every test in two zones to catch this |
| Checklist | A task dragged down one slot snaps back with no message | Positions sent by the browser are places in a dense list (0, 1, 2), but stored `order_index` values had holes after a delete, and both the client helper and the SQL function compared one with the other | Compare positions, never a stored index with a position (`reorderItems`, migration 0027). `deleteChecklistItem` and a phase change renumber the phase they leave |
| Checklist | Deleted template tasks come back | The loader seeded whenever it found no tasks, so a cleared list looked like a first run | `getChecklistItems` only reads. The template is inserted once, by `createRelocation`, when the user's first move is created |
| Database | A function loses `SECURITY INVOKER` or `STRICT` after a later migration | `CREATE OR REPLACE FUNCTION` keeps the owner and the grants but resets every other attribute to what the new statement says | Repeat the security attributes in every migration that replaces a function, as 0027 does |
